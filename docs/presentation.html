⚡ Installation

💡 Ce qu'il vous faut :
  • Un système Linux (Arch ou tout autre distribution)
  • Python 3.10 ou plus récent
  • Aucun droit administrateur requis pour démarrer

Installation rapide

[ -d omega-serv ] && echo "ℹ️ Déjà extrait ici, étape ignorée." || tar -xzf omega-serv.tar.gz
cd omega-serv/
chmod +x install.sh
./install.sh

Le script install.sh s'occupe de tout :

  1. Crée un environnement isolé pour l'application
  2. Installe le paquet (aucune dépendance externe pour le cœur du serveur)
  3. Rend le lanceur exécutable
  4. Ajoute la commande serv à votre terminal

Lancer Omega-Serv

./omega-serv.sh
# ou simplement 'serv' dans un NOUVEAU terminal

Au premier lancement, un assistant de démarrage vous guide en 8 étapes pour créer votre première configuration et mettre le serveur en route — sans connaître une seule commande.

Outils optionnels recommandés

L'interface fonctionne en mode dégradé si ces outils sont absents :

  • lnav — analyse avancée des logs fusionnée dans l'écran Gestion des logs ; message d'erreur clair et explicite si l'exécutable est introuvable, aucun crash.
  • python-psutil — installé automatiquement par pip install -e . dans tous les cas, mais le préinstaller via le gestionnaire système évite à pip de devoir compiler son wheel localement.
# Arch Linux et dérivés
sudo pacman -S openssl certbot lnav python-psutil

# Debian/Ubuntu et dérivées
sudo apt install openssl certbot lnav python3-psutil

# Fedora
sudo dnf install openssl certbot lnav python3-psutil

Mise à jour

Si `omega-serv/` existe déjà (installation précédente, conserve les parametres), **ne lancez jamais `tar` depuis l'intérieur de ce dossier** : il tenterait de créer un `omega-serv/omega-serv/` imbriqué et échouerait. Contrairement à omega-fire, `install.sh` ne touche jamais aux permissions du dossier (aucune étape n'y demande `sudo`) ? donc pas de risque de dossier appartenant à `root` ici, une extraction directement par-dessus l'installation existante est sûre.

Lancer

# Depuis le dossier PARENT de omega-serv/ (jamais depuis l'intérieur) 
tar -xzf omega-serv.tar.gz
cd omega-serv/
./install.sh

🎯 Vos premiers pas en 5 minutes

1 — Lancez l'assistant

Depuis l'accueil, choisissez Assistant premier lancement. Il vous pose quelques questions simples : quel profil utiliser, quelle adresse et quel port écouter, voulez-vous HTTPS...

2 — Déposez vos fichiers

Copiez votre site dans le dossier webroot/. Vos fichiers sont immédiatement servis — pas de redémarrage nécessaire.

3 — Activez HTTPS

L'assistant propose de générer un certificat en un clic. Pour vos tests locaux, l'auto-signé suffit. Pour plusieurs appareils, une petite autorité locale fait le travail. Inclus aussi HTTPS Auto (ACME via Cerbot "Let's Encrypt" à activer pour renouvellement auto) pour exposition WEB.

4 — Installez le service

Pour que le serveur démarre automatiquement avec la machine, laissez-vous guider : l'installation du service systemd est proposée à la fin de l'assistant.

5 — Activez la sécurité

Le WAF, l'authentification HTTP Basic, le cache, les redirections... Tout s'active depuis un menu unique. Un tableau récapitule à chaque instant ce qui est actif.

6 — Surveillez en direct

L'écran État & Ressources vous montre en temps réel le trafic, les erreurs, les ressources consommées, et même les menaces détectées par Active Defense.

💡 Ce qui fait la différence

🛡️ La sécurité n'est pas une option

  • Dès le premier lancement, le serveur est protégé contre les abus basiques (méthodes dangereuses bloquées, en-têtes de sécurité, CSP par défaut)
  • Ces protections ne peuvent pas être désactivées par erreur — elles sont dans le cœur du serveur
  • Le serveur refuse de tourner en tant que root : il vous protège de vos propres erreurs

🎛️ Une interface qui prend soin de vous

  • Chaque écran a sa propre aide contextuelle (touche F1)
  • Les modifications sensibles demandent confirmation — jamais de mauvaise surprise
  • Le serveur vous dit toujours s'il faut le recharger ou le redémarrer après un changement
  • Guide complet intégré, avec FAQ et exemples concrets, exportable en HTML

🔍 Un vrai compagnon de sécurité

  • WAF optionnel : signatures, limitation de débit, liste de blocage
  • Active Defense : détection des comportements hostiles, leurres intelligents, journalisation enrichie
  • Incidents documentés avec chronologie et exports d'indicateurs de compromission
  • Simulation en dry-run : vérifier une règle avant de l'activer

🧩 Une architecture modulaire

  • Vous activez uniquement ce dont vous avez besoin
  • Chaque module vit dans son espace : FastCGI/PHP, TLS, redirections, cache, authentification, upload
  • Le multi-instance vous permet de faire tourner plusieurs serveurs sur la même machine
  • Sauvegarde et restauration de configuration en un clic

📊 Un tableau de bord complet

  • Logs consultables, suivables en direct, fusionnables via lnav
  • Statistiques horaires, top IPs, répartition par code de statut
  • Rotation et archivage automatiques ou manuels
  • Fusion multi-logs pour les enquêtes

🎓 Pensé pour apprendre

  • Chaque champ est expliqué avec un exemple concret
  • Un simulateur de requête pour comprendre le routage
  • La FAQ répond aux pièges réellement rencontrés
  • Vous n'avez jamais besoin d'éditer un fichier de configuration à la main

🧩 Modules disponibles

Tous désactivés par défaut — vous activez uniquement ce dont vous avez besoin :

Module Rôle
WAFFiltrage applicatif (signatures, limitation de débit, liste de blocage)
TLSHTTPS avec certificat auto-signé ou signé par une autorité locale
AuthentificationHTTP Basic par zone (protège des dossiers ou applications)
FastCGI/PHP-FPMExécution PHP via un serveur PHP-FPM externe
Reverse proxyRedirection des requêtes vers un backend, avec répartition de charge et WebSocket
CacheContrôle du cache navigateur par zone et par extension
UploadZones d'upload confinées avec quotas
Active DefenseLeurres intelligents, détection comportementale, incidents et exports IoC

🔒 Une sécurité qui ne se compromet pas

  • Le serveur refuse de démarrer en tant que root — c'est une décision volontaire pour votre sécurité
  • Liste blanche de méthodes HTTP, validation stricte des en-têtes, rejet de l'ambiguïté Content-Length
  • En-têtes de sécurité (CSP, HSTS, X-Content-Type-Options...) envoyés à toute réponse, y compris les erreurs
  • Protection contre le path traversal, le double-encodage, les liens symboliques mal placés
  • Résolution des adresses IPv4-mappées-IPv6 avant toute vérification (contre un contournement connu)
  • Tests de propriétés (hypothesis) sur le parseur HTTP et le résolveur de chemin
💡 Bon à savoir : Le profil hardened recommande explicitement de placer Omega-Serv derrière un reverse proxy pour une exposition Internet réelle. Ce n'est pas une limitation — c'est une posture prudente.
